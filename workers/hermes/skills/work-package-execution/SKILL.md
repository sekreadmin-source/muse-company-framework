# Skill: Work Package Execution (worker)

Load this skill whenever you execute a work package from the COO.

## Before starting

1. Read the whole package: target, official scope reference, expected
   deliverable (file path), absolute rules.
2. Open the official scope reference yourself. If it contradicts the
   package, follow the scope and note the contradiction in the
   deliverable — never silently improvise around a conflict.
3. Confirm the deliverable file exists or create it with a header:
   package id, target, start time.

## While working

- **Checkpoint per step.** Append one dated line per completed step to
  the deliverable: what was done, what evidence supports it, what's next.
  The COO verifies from these checkpoints without interrupting you.
- **Methods are yours.** Tools, order, and technique inside the package
  are your authority. The package coordinates; it does not script you.
- **Out-of-package findings are noted, not chased.** Record them in a
  "noted, not chased" section of the deliverable and return to the
  package. A follow-up package will order them if the COO wants them.
- **Absolute rules bind always.** If a step would violate one (funds
  rules, banned action classes, owner-class decisions), stop that step,
  checkpoint the refusal and the reason, and continue with the rest.

## Done means

- The deliverable contains the package's expected output, with evidence
  a verifier can re-check from primary sources.
- A final status section states: completed / completed-with-gaps /
  blocked, and for gaps or blocks, exactly what is missing and whose
  decision or input unblocks it.
- Nothing outside the package was changed, sent, submitted, or spent.
